# 多菜餐次改造设计

## 目标

将早餐、午餐、晚餐从单道菜餐格改为多道菜列表。用户可以在同一餐中连续添加菜谱或临时菜名，并单独删除每道菜。

## 数据结构

餐格从单个对象改为：

```js
{
  dishes: [
    { recipeId: "r01", name: "小米粥", source: "library" },
    { recipeId: "r02", name: "鸡蛋饼", source: "library" }
  ]
}
```

读取旧数据时，如果餐格仍是 `{ recipeId, name, source }`，自动归一化为 `{ dishes: [旧对象] }`。数据保存后使用新结构，不删除旧菜名或历史记录。

## 交互

- 点击餐格打开编辑面板，选择菜谱时追加到当前餐，不再替换已有菜。
- 不限制不同菜品的数量；同一餐再次选择相同 `recipeId` 时忽略重复项。
- 每道菜提供独立删除按钮。
- 编辑面板继续支持直接录入临时菜名。
- 餐格显示全部菜名；移动端按列表换行。
- 清空此餐仍删除整个餐格，并保留撤销能力。

## 自动规划

- 早餐目标为 2 道，午餐和晚餐目标各为 3 道。
- 保留用户已经添加的菜，只补齐不足数量。
- 同一餐不得重复同一道菜。
- 午晚餐优先组合主食、荤菜、素菜或汤；菜谱不足时允许退化为可用组合。

## 下游功能

- 今日菜单展示每餐全部菜品。
- 历史菜单复制整个 `dishes` 数组。
- 采购清单遍历每餐全部菜谱并合并食材。
- 归档和 JSON 备份保留多菜结构。

## 验收标准

1. 同一餐可以连续添加至少 4 道菜。
2. 删除一道菜不会影响同餐其他菜。
3. 旧的单菜餐格加载后正常显示。
4. 自动规划后早餐 2 道、午晚餐各 3 道。
5. 采购清单包含同餐所有菜谱的食材。
